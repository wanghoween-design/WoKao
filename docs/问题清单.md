## 🎯 一、项目全局逻辑与架构重塑

「我考」的核心产品闭环应为：
```mermaid
flowchart LR
    A[① 考生身份与精力画像] --> B[② 多目标选择/考研+考公]
    B --> C[③ 实时考情与招生政策检索]
    C --> D[④ LangGraph 智能融合排期]
    D --> E[⑤ 交互看板/甘特图/周日程]
    E --> F[⑥ 日历导出.ics & 闭环反馈微调]
```

## 🔍 二、问题清单明细（按模块与优先级）

### 模块一：AI Agent 链路与大模型调用健壮性

| 编号 | 问题描述 | 严重级别 | 根因分析 | 预期修复方案 |
| :--- | :--- | :--- | :--- | :--- |
| **ISSUE-01** | **多目标计划 JSON 提取脆弱，易被截断导致看板崩溃** | 🔴 P0 (阻塞级) | `_extract_json()` 仅靠正则匹配，长 JSON 输出若被模型 Max Tokens 截断或少括号，直接导致 `json.loads` 失败，静默回退纯 Markdown，前端精美看板直接失效。 | 引入 `json_repair` 容错修复机制与 Pydantic 结构校验，确保任何情况都能解析出合法的多轨任务结构。 |
| **ISSUE-02** | **融合多目标生成绕过 LangGraph 架构** | 🔴 P0 (架构级) | `run_fused_agent` 和 `_run_fused_with_search` 在 `agent.py` 中写死 `for` 循环，未纳入 LangGraph 编译图，失去状态追踪与检查点恢复能力。 | 将多目标分析、政策检索、时间冲突消解、周日程生成重构为标准 LangGraph StateGraph 节点。 |
| **ISSUE-03** | **长耗时生成缺乏阶段进度反馈** | 🟡 P1 (体验级) | 开启联网检索和复杂多目标生成时耗时达 30s~90s，长轮询无状态进度，用户端易误认为卡死。 | 建立清晰的分步进度状态流与友好过渡动画，杜绝界面假死感。 |
| **ISSUE-04** | **多模型兼容与异常诊断提示不够友好** | 🟡 P1 (稳定性) | 当用户配置国产大模型（如 GLM-5.2、通义千问、DeepSeek）时，部分网关不支持 `tool_choice: function` 强约束，可能引发报错。 | 增强对非标准 OpenAI 兼容网关的自适应探测与降级容错机制，抛出清晰中文诊断。 |

### 模块二：考情数据、爬虫与联网检索层

| 编号 | 问题描述 | 严重级别 | 根因分析 | 预期修复方案 |
| :--- | :--- | :--- | :--- | :--- |
| **ISSUE-05** | **Playwright 抓取全局锁导致高延迟与并发串行** | 🔴 P0 (性能级) | `_pw_lock` 全局互斥锁导致所有页面抓取完全串行，且在无环境或网络卡顿时容易挂死请求。 | 确立「Requests + 智能文本抽取」高速主干与「Playwright 渲染」可选增强分级机制，严控超时与连接回收。 |

### 模块三：后端架构、安全与数据持久化

| 编号 | 问题描述 | 严重级别 | 根因分析 | 预期修复方案 |
| :--- | :--- | :--- | :--- | :--- |
| **ISSUE-07** | **Session 缺乏过期机制与异常防护** | 🔴 P0 (安全级) | 会话表 `sessions` 中的 Token 永不过期，缺少 `expires_at` 校验；认证接口缺少频率限制。 | 增加 Session 有效期检查（默认 7 天），过期自动提示重新登录；关键接口增加基础防护。 |
| **ISSUE-08** | **SQLite 并发写入锁隐患** | 🟡 P1 (架构级) | 未显式开启 SQLite WAL 模式，高并发读写时易抛 `database is locked`。 | 数据库初始化时开启 WAL 模式（`PRAGMA journal_mode=WAL;`），提高读写并发能力。 |
| **ISSUE-09** | **数据删除缺少级联一致性保障** | 🟡 P1 (数据级) | 计划删除或重置时缺少外键约束联动。 | 规范数据操作事务，补充关联清理逻辑，确保无孤儿残留数据。 |

## 🛠️ 三、修复执行路线与验收准则

1. **第一阶段：后端与 Agent 链路核心加固（ISSUE-01 ~ ISSUE-09）**
   - 解决 JSON 截断容错，重构多目标 LangGraph 状态图；
   - 优化检索与数据库并发，完善 Session 过期与安全；
   - 新增 `.ics` 日历导出 API 与数据生成能力。
2. **第二阶段：前端交互与产品闭环升级（ISSUE-10 ~ ISSUE-12）**
   - 实现 `.ics` 日历下载、Markdown/打印导出、打卡统计；
   - 升级多轨看板与周日程交互，增强移动端响应式与刷新恢复。
3. **第三阶段：清理、工程化与全套自动化测试（ISSUE-13 ~ ISSUE-15）**
   - 清理废弃文件，优化 `start.bat` / `setup_env.bat`；
   - 编写并执行全套 `pytest` 测试，确保所有测试 100% 通过；
   - 重新编译前端（`npm run build`），端到端启动验收。
